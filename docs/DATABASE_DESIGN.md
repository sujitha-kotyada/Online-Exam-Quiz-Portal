# Database Design & Data Modeling (MongoDB / Mongoose)

This document provides complete documentation of the database architecture, schema definitions, indexing strategies, relationships, and integrity rules implemented in the **Online Exam & Quiz Portal**.

---

## 1. Entity Relationship (ER) Overview

```
 ┌──────────────┐             1:N              ┌──────────────┐
 │     User     │ ────────────────────────────>│     Exam     │
 │ (Teacher)    │ (createdBy)                  └──────────────┘
 └──────────────┘                                      │ 1:N
        │ 1:N                                          │ (examId)
        │ (studentId)                                  ▼
        │                                      ┌──────────────┐
        ▼                                      │   Question   │
 ┌──────────────┐         1:1 (attemptId)      └──────────────┘
 │   Attempt    │ <────────────────────────────┐
 └──────────────┘                              │
        │ 1:N                                  │
        ▼ (studentId)                          ▼
 ┌──────────────┐             1:N              ┌──────────────┐
 │    Result    │ <────────────────────────────│     Exam     │
 └──────────────┘ (studentId, examId)          └──────────────┘
```

## 2. Collections & Schema Specifications

### 2.1. `users` Collection
Stores registered user accounts (Students and Teachers).

| Field | Type | Attributes | Description |
| :--- | :--- | :--- | :--- |
| `_id` | ObjectId | Primary Key | Autogenerated unique document ID |
| `name` | String | Required, Trim, Max: 100 | Full name of the user |
| `email` | String | Required, Unique, Lowercase, Indexed | Normalized unique email address |
| `passwordHash` | String | Required, `select: false` | 10-round bcrypt salted password hash |
| `role` | String | Required, Enum: `['student', 'teacher']`, Default: `'student'` | Account authorization role |
| `createdAt` | Date | Autogenerated | Timestamp of account creation |
| `updatedAt` | Date | Autogenerated | Timestamp of last profile update |

**Integrity Rule:** `passwordHash` is excluded by default in schema queries and explicitly deleted in the `toJSON()` method to prevent credential leaks.

---

### 2.2. `exams` Collection
Stores assessment metadata, durations, review policies, and scheduling rules.

| Field | Type | Attributes | Description |
| :--- | :--- | :--- | :--- |
| `_id` | ObjectId | Primary Key | Autogenerated unique document ID |
| `title` | String | Required, Trim, Max: 200 | Title of the examination |
| `description` | String | Optional, Trim | Syllabus and overview notes |
| `instructions` | String | Optional, Trim | Candidate exam guidelines |
| `durationMinutes` | Number | Required, Min: 1, Max: 300 | Time allocated for the assessment |
| `startTime` | Date | Optional, Default: `null` | Earliest time exam can be attempted |
| `endTime` | Date | Optional, Default: `null` | Deadline after which attempts close |
| `createdBy` | ObjectId | Required, Ref: `'User'`, Indexed | Foreign key to the creating Teacher |
| `status` | String | Enum: `['draft', 'published', 'archived']`, Default: `'draft'` | Publishing workflow status |
| `maxAttempts` | Number | Default: 1, Min: 1 | Max completed attempts allowed per student |
| `allowAnswerReview` | Boolean | Default: `true` | Allows post-submission answer key inspection |
| `createdAt` | Date | Autogenerated | Timestamp of exam creation |
| `updatedAt` | Date | Autogenerated | Timestamp of last modification |

**Indexes:**
- Compound index: `{ createdBy: 1, status: 1 }` (optimizes faculty dashboard queries)
- Compound index: `{ status: 1, startTime: 1, endTime: 1 }` (optimizes student catalog queries)

---

### 2.3. `questions` Collection
Stores multiple-choice questions (MCQs), options, answer keys, marks, and explanations.

| Field | Type | Attributes | Description |
| :--- | :--- | :--- | :--- |
| `_id` | ObjectId | Primary Key | Autogenerated unique document ID |
| `examId` | ObjectId | Required, Ref: `'Exam'`, Indexed | Foreign key to parent examination |
| `questionText` | String | Required, Trim | The question text displayed to candidates |
| `options` | Array of Subdocuments | Min: 2, Max: 6 | Array of `{ id: String, text: String }` |
| `correctAnswer` | String | Required, Trim | The option `id` corresponding to the correct choice |
| `marks` | Number | Required, Min: 1, Default: 1 | Positive score awarded for correct answer |
| `order` | Number | Default: 0 | Sequential sequence for display |
| `topic` | String | Default: `'General'` | Categorization tag for faculty analytics |
| `explanation` | String | Optional, Trim | Explanatory rationale displayed post-exam |
| `createdAt` | Date | Autogenerated | Timestamp of question creation |

**Indexes:**
- Compound index: `{ examId: 1, order: 1 }` (guarantees fast, ordered retrieval)

---

### 2.4. `attempts` Collection
Stores student assessment sessions, authoritative timing bounds, and saved responses.

| Field | Type | Attributes | Description |
| :--- | :--- | :--- | :--- |
| `_id` | ObjectId | Primary Key | Autogenerated unique document ID |
| `studentId` | ObjectId | Required, Ref: `'User'`, Indexed | Foreign key to student |
| `examId` | ObjectId | Required, Ref: `'Exam'`, Indexed | Foreign key to target examination |
| `attemptNumber` | Number | Required, Default: 1 | 1st, 2nd, etc. attempt counter |
| `startedAt` | Date | Required, Default: `Date.now` | Authoritative server start timestamp |
| `deadline` | Date | Required | Authoritative server-calculated expiration |
| `submittedAt` | Date | Default: `null` | Timestamp when final submission occurred |
| `status` | String | Enum: `['in-progress', 'submitted', 'expired']`, Default: `'in-progress'` | Attempt lifecycle state |
| `answers` | Array of Subdocuments | Embedded array | Saved student choices: `{ questionId, selectedOption, savedAt }` |

**Indexes:**
- Compound index: `{ studentId: 1, examId: 1, attemptNumber: 1 }`
- Compound index: `{ studentId: 1, examId: 1, status: 1 }` (enables O(1) active session lookup for refresh recovery)

---

### 2.5. `results` Collection
Stores immutable final grades, performance metrics, and question-by-question scoring breakdowns.

| Field | Type | Attributes | Description |
| :--- | :--- | :--- | :--- |
| `_id` | ObjectId | Primary Key | Autogenerated unique document ID |
| `attemptId` | ObjectId | Required, Ref: `'Attempt'`, Unique, Indexed | 1:1 Foreign key to Attempt |
| `studentId` | ObjectId | Required, Ref: `'User'`, Indexed | Foreign key to Student |
| `examId` | ObjectId | Required, Ref: `'Exam'`, Indexed | Foreign key to Exam |
| `score` | Number | Required, Min: 0 | Total marks earned by candidate |
| `totalMarks` | Number | Required, Min: 0 | Total possible marks for the exam |
| `percentage` | Number | Required, Min: 0, Max: 100 | Percentage score (rounded to 2 decimals) |
| `correctCount` | Number | Required, Min: 0 | Number of correct responses |
| `incorrectCount` | Number | Required, Min: 0 | Number of incorrect responses |
| `unansweredCount` | Number | Required, Min: 0 | Number of unselected questions |
| `breakdown` | Array of Subdocuments | Embedded array | Snapshot of each question evaluation |

**Indexes:**
- Unique index: `{ attemptId: 1 }` (guarantees idempotent submissions)
- Compound index: `{ examId: 1, studentId: 1 }` (speeds up teacher cohort analytics)
- Compound index: `{ studentId: 1, createdAt: -1 }` (speeds up student history page)

## 3. Data Integrity & Cascading Strategies

1. **Cascading Delete on Exams:** When a teacher deletes an exam via `DELETE /api/exams/:examId`, `examService.deleteExam()` executes:
   - `Question.deleteMany({ examId })`
   - `Attempt.deleteMany({ examId })`
   - `Result.deleteMany({ examId })`
   - `Exam.findByIdAndDelete(examId)`
   This prevents orphaned question or submission documents in the database.
2. **Idempotency Strategy:** Submission evaluation uses `Result.findOneAndUpdate({ attemptId }, ..., { upsert: true, new: true })`. If duplicate submit requests hit the server concurrently, MongoDB's unique index on `attemptId` prevents duplicate document creation.
